## Key Entities (신규)

### A. 차량과 운전

- **차량 종류**: 어린이가 고를 수 있는 다섯 가지 차량 외형(버기, 지프, 트럭, 왜건, 바나나 자동차). 운전 성능의 우열이 없다.
  - 필수 속성: 표시 이름(한국어), 외형 자료, 연결된 자료 출처
  - 관계: 5종 모두 **공통 운전 성능** 1개를 공유 / 차량 종류 1 : 자료 출처 1 / **현재 실행 상태**의 선택 차량, **참가 차량**의 외형이 이 엔티티를 참조
  - 비고: 선택한 차량 종류는 PRD 저장 대상이 아니므로 재접속 시 기억하지 않는다
  - 근거: 첫 버전의 범위(차량 선택·차량 성능), 제공된 차량 모델, 용어집 "차량 종류"

- **공통 운전 성능**: 모든 차량 종류와 컴퓨터 차량이 함께 쓰는 단 하나의 성능 묶음.
  - 필수 속성: 최고속도, 가속, 제동, 조향, 후진 성능, 판정용 차체 크기(외형과 무관하게 동일 — 해석)
  - 관계: 차량 종류(5) · 참가 차량(4)이 모두 참조
  - 비고: 구체 값은 "정상 주행 약 5분" 목표에 맞춰 트랙 점검에서 조정. 교육용 마을과 전용 트랙에서 다른 값을 쓸지는 plan 결정(어느 경우든 차량 종류 간에는 동일해야 함)
  - 근거: 첫 버전의 범위(차량 성능), 레이싱 규칙, 제공된 차량 모델 > 개발 시 확인할 사항

- **운전 입력**: 어린이 플레이어가 누르는 조작 버튼의 현재 상태.
  - 필수 속성: 좌조향, 우조향, 액셀, 브레이크 — 각각 눌림/놓임 / 후진 전환 — 전환 요청(누를 때 1회)
  - 관계: 플레이어의 **주행 상태**를 바꾼다. 일시정지·화면 숨김 시 전부 놓임으로 초기화
  - 근거: 운전 조작과 화면 > 터치 조작

- **주행 상태**: 차량 한 대가 지금 어떻게 움직이고 있는지.
  - 필수 속성: 주행 방향(전진/후진), 정지 여부, 속도, 공간 안의 위치와 향하는 방향
  - 관계: 플레이어 차량(안전 연습·레이싱)과 컴퓨터 차량(레이싱)이 각각 1개씩 가진다
  - 근거: 터치 조작(후진 전환은 정지 상태에서만, 전진·후진을 그림으로 구분)

### B. 안전 연습

- **교육용 마을**: 신호등·횡단보도·교차로·보도·보행자가 있는 안전 연습 공간. 첫 버전 1개.
  - 필수 속성: 도로·보도·정지 위치(정지선)·횡단보도·교차로 배치, 세 안전 상황의 장소
  - 관계: 교통 신호 N, 등장 보행자 N, 안전 상황 3개의 장소를 포함
  - 근거: 첫 버전의 범위(교육 공간), 용어집 "교육용 마을"

- **교통 신호**: 교육용 마을의 차량 신호와 보행자 신호. 둘은 반드시 구분해 보여 준다.
  - 필수 속성: 신호 구분(차량/보행자), 현재 신호 상태, 설치 위치(어느 횡단보도·교차로), 색 외의 구별 표시(그림·형태)
  - 관계: 안전 상황(특히 "신호 기다리기")의 판정 조건이 된다
  - 근거: 교육 표현 원칙(차량 신호와 보행자 신호 구분), 화면과 카메라(색상만으로 상태 설명 금지)

- **등장 보행자**: 교육용 마을에서 길을 건너는 컴퓨터 제어 인물. 어린이가 조작하지 않는다.
  - 필수 속성: 위치, 상태(보도 대기 / 횡단 중 / 건너기 완료)
  - 관계: 교육용 마을에만 존재하며 전용 트랙에는 없다. 보행자 시점 안내의 "관점 주인공"이 된다
  - 비고: "횡단 전 주변 차량 확인하기"에 플레이어 외의 주변 차량 연출이 필요한지는 콘텐츠 설계(plan)에서 정함
  - 근거: 레이싱 규칙(보행자 미배치), 안전 연습과 교육 내용 표

- **안전 연습**: 운전 조작과 세 가지 보행 안전 상황을 익히는 반복형 교육 모드. 처음 이용할 때의 튜토리얼과 완료 후 다시 고르는 연습은 같은 모드다.
  - 필수 속성: 조작 익히기(조향·액셀·브레이크·후진) 단계 [NEEDS CLARIFICATION NC-1], 안전 상황 3개, 상황별 완료 여부(현재 실행 상태에 보관)
  - 관계: 교육용 마을에서 진행 / 안전 상황 3개로 구성 / 세 상황 완료가 **레이싱 열림**을 일으킨다
  - 근거: 플레이 흐름 3~6, 용어집 "안전 연습"

- **안전 상황**: 안전 연습 안의 세 주제. 고정 3종.
  - 필수 속성: 주제, 운전 체험 내용, 필요한 안전 행동의 순서, 잘못된 행동(실패 조건) 목록, 보행자 시점 안내 내용, 장소, 근거로 삼는 공공 안내(행정안전부·도로교통공단)
  - 관계: 안전 상황 1 : 연습 구간 1..N / 안전 상황 1 : 보행자 시점 안내 1 이상
  - 상황별 필요 행동(PRD 표를 도메인 단계로 옮김 — 해석):

    | 안전 상황 | 운전 중 필요한 행동 | 보행자 시점 안내로 전달할 내용 |
    |---|---|---|
    | 신호 기다리기 | 차량 신호 구분 → 정해진 위치에 정지 → 진행 신호(안전한 때)까지 대기 → 출발 | 보행자 신호 확인, 보도에서 기다리기, 아직 건너기 전이면 깜빡이는 초록불에 들어가지 않기 |
    | 횡단 전 주변 차량 확인하기 | 횡단보도 접근 → 완전히 정지 → 보행자가 건너는 동안 대기 → 출발 | 초록불로 바뀌어도 바로 뛰지 않기, 좌우와 차량이 멈췄는지 확인 후 걸어서 건너기 |
    | 교차로의 회전 차량 주의하기 | 회전 전 보행자 확인(정지) → 보행자가 건너는 동안 대기 → 보행자가 다 건넌 뒤 회전 | 도는 차가 있는지 살피기, 운전자에게 내가 잘 안 보일 수 있음을 이해하기 |

  - 비고: 회전 방향(우회전/좌회전)과 구체 신호 구성은 PRD가 지정한 공공 안내를 기준으로 콘텐츠 설계에서 구체화(PRD "…를 기준으로 구체화합니다")
  - 근거: 안전 연습과 교육 내용 표, 연습의 완료 기준

- **연습 구간**: 실패했을 때 다시 시작하는 단위. 안전 상황 하나는 구간 하나 이상으로 나뉜다.
  - 필수 속성: 시작 위치, 이 구간에서 인정해야 할 안전 행동, 실패 조건
  - 관계: 안전 상황에 속한다. 실패하면 같은 구간을 처음부터 다시 한다
  - 비고: 상황을 몇 개의 구간으로 나눌지는 plan·콘텐츠 설계 결정
  - 근거: 플레이 흐름 4("그 구간을 반복"), 교육 표현 원칙("해당 구간의 재시도")

- **안전 행동**: 멈추기·살피기·기다리기·안전한 때 출발하기(용어집). 연습 완료를 판정하는 행동이며 빠른 도착과 구분한다.
  - 게임 안 판정 단위: 정지(정해진 위치에서 완전히 멈춤), 대기(안전 조건이 충족될 때까지 멈춤 유지), 출발(안전 조건 충족 후 움직임)
  - 비고(해석): "살피기"는 별도 조작 버튼이 없으므로 정지·대기 행동과 보행자 시점 안내로 전달한다. PRD 완료 기준도 "정지·대기·출발 행동"으로 적혀 있다
  - 근거: 용어집 "안전 행동", 연습의 완료 기준

- **보행자 시점 안내**: 운전한 같은 장소를 보행자 입장에서 보여 주고 음성·그림으로 걸을 때의 행동을 설명하는 장면. 조작 없음(보행자 조작 모드가 아님).
  - 필수 속성: 연결된 안전 상황, 장소, 그림 설명, 음성 설명, 경험 완료 여부 [NEEDS CLARIFICATION NC-4]
  - 관계: 안전 상황 1 : 안내 1 이상. 경험 완료가 상황 완료의 필수 조건
  - 비고: 소리를 꺼도 그림·시범만으로 내용을 확인할 수 있어야 한다
  - 근거: 안전 연습과 교육 내용 첫 문단, 연습의 완료 기준, 용어집 "보행자 시점 안내"

- **현재 실행 상태**: 게임 페이지를 연 뒤 닫거나 새로 고치기 전까지만 유지되는 진행 정보. 저장하지 않는다.
  - 필수 속성: 선택한 차량 종류, 레이싱 열림 여부, 상황별 완료 여부(이번 실행), 저장 기능 사용 가능 여부, 소리 활성화 여부, (저장 불가 시) 이번 실행의 최고 기록·소리 설정 값
  - 관계: 브라우저 저장 기록을 읽어 초기값을 정하고, 바뀐 값은 저장 대상 항목만 다시 저장한다
  - 근거: 브라우저에 남기는 기록(저장 불가 시 현재 실행 중 완료로 레이싱 이용)

### C. 레이싱

- **전용 트랙**: 일반 도로와 구분되고 보행자가 들어오지 않는 레이싱 공간. 첫 버전 1개.
  - 필수 속성: 정해진 진행 방향, 결승선, 순서가 정해진 구간(통과 확인 지점), 구간별 안전 복귀 위치, 고정 바퀴 수(1 또는 2)
  - 관계: 레이싱 경기의 장소 / 최고 기록은 트랙당 1개
  - 근거: 첫 버전의 범위(레이싱 공간), 레이싱 규칙, 용어집 "전용 트랙"

- **레이싱 경기**: 한 번의 경주. 재도전하면 새 경기가 된다.
  - 필수 속성: 전용 트랙, 바퀴 수, 참가 차량 4대, 경기 시간(일시정지 시간 제외), 경기 상태, 순위(파생 값 — 저장하지 않음)
  - 관계: 전용 트랙 1, 참가 차량 4(플레이어 1 + 컴퓨터 3). 플레이어가 정상 완주하면 완주 기록 1개를 만든다
  - 근거: 레이싱 규칙, 플레이 흐름 7

- **참가 차량**: 경기에 참가한 차량 한 대.
  - 필수 속성: 구분(플레이어/컴퓨터), 차량 종류(외형), 주행 상태, 코스 진행도, 완주 여부, 완주 순서
  - 컴퓨터 차량 추가 속성: 주행 경로, 반응(난이도 조절 수단 — 성능 값이 아님)
  - 관계: 공통 운전 성능을 따른다. 컴퓨터 차량의 외형 [NEEDS CLARIFICATION NC-8]
  - 근거: 레이싱 규칙("컴퓨터 차량도 공통 주행 규칙…난이도는 주행 경로와 반응")

- **코스 진행도**: 참가 차량이 정상 진행 방향으로 얼마나 왔는지. 순위와 바퀴 완료 판정의 근거.
  - 필수 속성: 완료한 바퀴 수, 이번 바퀴에서 순서대로 통과한 구간, 현재 구간 안의 정방향 위치
  - 관계: 참가 차량 1 : 진행도 1
  - 근거: 레이싱 규칙(순위 기준, 후진·역주행·복귀로 이득 불가)

- **완주 기록**: 정해진 진행 방향과 코스를 따라 필요한 바퀴 수를 모두 마친 경기의 소요 시간.
  - 필수 속성: 완주 시간, 플레이어 순위(결과 화면 표시용)
  - 관계: 레이싱 경기에서 생성. 저장하지 않으며 최고 기록 갱신 판단에만 쓴다
  - 근거: 용어집 "완주 기록", 레이싱 규칙(완주 화면)

- **최고 기록**: 해당 트랙에서 가장 짧은 정상 완주 시간.
  - 필수 속성: 완주 시간, 대상 트랙
  - 관계: 전용 트랙 1 : 최고 기록 0..1. 차량 종류·순위와 무관(해석: PRD가 "해당 트랙의 최고 기록"으로만 정의). 브라우저 저장 대상
  - 비고: 어디에 보여 줄지 PRD에 없음 [NEEDS CLARIFICATION NC-6]
  - 근거: 레이싱 규칙, 용어집 "완주 기록", 브라우저에 남기는 기록

### D. 소리·저장·출처

- **소리 설정**: 소리 종류별 켬/끔.
  - 필수 속성: 배경음 켬/끔, 안내·효과음 켬/끔 — 설정 단위 [NEEDS CLARIFICATION NC-5]
  - 관계: 브라우저 저장 대상
  - 근거: 소리와 배경음악

- **브라우저 저장 기록**: 해당 브라우저에만 남는 기록. 개인정보 없음.
  - 필수 속성(3개만): 튜토리얼 전체 완료 여부, 레이싱 최고 기록, 소리 설정
  - 관계: 실행 시작 시 읽어 현재 실행 상태를 초기화. 기기·브라우저 간 공유 없음
  - 비고: 저장 기록은 어린이·보호자가 지우거나 바꿀 수 있는 값이므로 읽은 값을 그대로 믿지 않는다(해석 — BR-034)
  - 근거: 첫 버전의 범위(저장), 브라우저에 남기는 기록, 플레이 흐름 마지막 문단

- **자료 출처(크레딧)**: 게임에 쓴 외부 자료의 출처·라이선스 표시.
  - 필수 속성: 자료 종류(차량 모델 / 배경음악 곡 / 녹음 음원 / 효과음 / 안내 음성), 작품명, 제작자(곡은 작곡·편곡·연주를 구분), 원출처 링크, 라이선스 이름·링크, 변경 여부·변경 내용, 사용조건 확인 결과와 확인일
  - 관계: 차량 종류 5개는 각각 1개씩(CC BY 3.0, 2026-10-12 확인). 음원은 아직 미정
  - 근거: 제공된 차량 모델, 소리와 배경음악, 완성 기준(자료 사용)

### 엔티티 관계 요약

```
차량 종류(5) ──공유──> 공통 운전 성능(1)
차량 종류 1 ── 1 자료 출처
현재 실행 상태 ──선택 차량──> 차량 종류
안전 연습 ──장소──> 교육용 마을 ──포함──> 교통 신호(N), 등장 보행자(N)

안전 상황 ──요구──> 안전 행동(순서) + 보행자 시점 안내(1 이상)

레이싱 경기 ──(플레이어 정상 완주)──> 완주 기록 ──(더 짧으면)──> 최고 기록
브라우저 저장 기록 = { 튜토리얼 전체 완료 여부, 최고 기록, 소리 설정 }
```

## State Transitions

### ST-01 게임 화면 흐름
- 상태: 로딩, 로딩 실패, 3D 미지원 안내, 시작 화면, 차량 선택, 안전 연습, 레이싱, 레이싱 결과, 크레딧
- 겹쳐 뜨는 상태: 가로 화면 안내(세로일 때), 일시정지(ST-06), 저장 불가 안내(ST-11)
- 전이 규칙:
  - (접속) → 3D 미지원 안내 (조건: 3D 표시 기능 사용 불가. 빈 화면 대신 안내, 진행 불가)
  - (접속) → 로딩 → 시작 화면 (조건: 필수 파일 로딩 완료. 로딩 진행 상태를 보여 줌)
  - 로딩 → 로딩 실패 → 로딩 (조건: 필수 파일 실패 → 다시 시도)
  - 시작 화면 → 차량 선택 (조건: 시작 버튼. 이 순간 소리 활성화 — ST-07)
  - 차량 선택 → 안전 연습 (조건: 레이싱 잠김 상태면 자동으로 안전 연습)
  - 레이싱 열림 이후: 시작 화면에서 안전 연습/레이싱 선택 → 차량 선택(다시 고를 수 있음) → 고른 모드 (해석: PRD 플레이 흐름 2·6단계를 함께 만족하는 순서)
  - 안전 연습 → 시작 화면 (조건: 세 상황 완료 후 / 중도 나가기 [NC-7])
  - 레이싱 → 레이싱 결과 (조건: 플레이어 완주. 시간 경과로는 넘어가지 않음)
  - 레이싱 → 시작 화면 (조건: 경기 중 나가기 [NC-7])
  - 레이싱 결과 → 레이싱 (조건: 재도전 — 같은 차량·같은 트랙의 새 경기, 가정)
  - 레이싱 결과 → 시작 화면
  - 시작 화면 ↔ 크레딧 (가정: 시작 화면에서 들어감)
- 근거: 플레이 흐름, GitHub Pages(로딩·재시도·3D 미지원), 화면과 카메라(세로 화면 안내)

### ST-02 레이싱 잠금
- 상태: 잠김, 열림
- 전이 규칙:
  - (실행 시작) → 열림 (조건: 저장 기록을 읽었고 튜토리얼 전체 완료 여부 = 완료)
  - (실행 시작) → 잠김 (조건: 기록 없음 / 읽기 실패 / 저장 기능 없음 / 값이 올바르지 않음)
  - 잠김 → 열림 (조건: 이번 실행에서 세 안전 상황을 모두 완료. 동시에 완료 여부 저장 시도. 저장 실패해도 열림 유지 + 기록이 남지 않는다는 안내)
  - 열림 → 잠김: 같은 실행 안에서는 없음. 다음 실행에서 기록이 없으면(데이터 삭제·다른 기기·이전 저장 실패) 잠김으로 시작
- 근거: 플레이 흐름 5·마지막 문단, 브라우저에 남기는 기록, 완성 기준(레이싱 열기)

### ST-03 안전 상황 진행 (상황별)
- 상태: 미완료, 진행 중, 위험 직전 멈춤(학습 연출), 보행자 시점 안내 중, 완료, 재연습 중
- 전이 규칙:
  - 미완료 → 진행 중 (조건: 상황 시작)
  - 진행 중 → 위험 직전 멈춤 (조건: 잘못된 행동 — 예: 정지 위치를 지나침, 진행 신호 전에 진입, 보행자 횡단 중 출발·회전, 보도 진입. 구체 목록은 콘텐츠 설계)
  - 위험 직전 멈춤 → 진행 중 (조건: 짧은 설명 후 같은 연습 구간을 처음부터 다시. 이미 통과한 앞 구간의 인정은 유지 — 해석)
  - 진행 중 → 보행자 시점 안내 중 (조건: 중요한 순간 도달 또는 필요 행동 수행 후)
  - 보행자 시점 안내 중 → 진행 중 (조건: 안내가 상황 중간에 나오는 구성일 때)
  - 보행자 시점 안내 중 / 진행 중 → 완료 (조건: 필요한 안전 행동을 모두 직접 수행 **그리고** 보행자 시점 안내 경험 완료. 끝 지점 도착·시간 경과만으로는 불가)
  - 완료 → 재연습 중 → 완료 유지 (조건: 다시 연습을 고름. 재연습에서 실패해도 완료는 취소되지 않음 — 해석)
  - 진행 중 / 위험 직전 멈춤 → 미완료 (조건: 중도 나가기. 이번 실행에서 완료한 다른 상황의 유지 여부 [NC-3])
  - 진행 중 ↔ 일시정지 (ST-06)
- 실패 횟수·시간제한 없음. 실패로 다른 상태(예: 게임 오버)로 가지 않는다
- 근거: 플레이 흐름 4, 교육 표현 원칙, 연습의 완료 기준

### ST-04 주행 방향
- 상태: 전진·정지, 전진·이동 중, 후진·정지, 후진·이동 중
- 전이 규칙:
  - 전진·정지 ⇄ 후진·정지 (조건: 후진 전환 요청. 정지 상태에서만)
  - 이동 중 전환 요청 → 상태 변화 없음 (현재 방향 그림 유지. 시범 안내 여부는 UX 결정)
  - 정지 → 이동 중 (조건: 액셀. 현재 주행 방향으로 이동)
  - 이동 중 → 정지 (조건: 브레이크 또는 감속)
  - 액셀과 브레이크 동시 → 브레이크로 처리
  - 모든 상태 → 입력 해제 (조건: 일시정지·화면 숨김·터치 취소)
  - 연습 구간 시작·경기 시작 시 → 전진·정지 (가정)
- 근거: 터치 조작

### ST-05 레이싱 경기
- 상태: 출발 준비, 진행, 일시정지, 플레이어 완주, 종료(결과 표시)
- 전이 규칙:
  - 출발 준비 → 진행 (조건: 출발 신호. 이 순간 경기 시간 시작 — 가정, PRD에 출발 연출 언급 없음)
  - 진행 ⇄ 일시정지 (ST-06과 같음. 일시정지 동안 경기 시간·모든 차량 정지)
  - 진행 → 플레이어 완주 (조건: 플레이어가 필요한 바퀴 수를 정방향으로 모두 완료. 이 순간 순위와 완주 시간 확정)
  - 플레이어 완주 → 종료 (결과 화면: 순위·완주 시간. 최고 기록 비교·저장 — BR-030)
  - 종료 → 출발 준비 (조건: 재도전. 진행도·시간·순위 초기화)
  - 진행 → 종료 없음 (조건: 시간 경과. 5분이 지나도 강제 종료하지 않음)
  - 일시정지 → (경기 포기) [NC-7]
- 근거: 레이싱 규칙, 플레이 흐름 7, 화면과 카메라(일시정지)

### ST-06 플레이 일시정지 (안전 연습·레이싱 공통)
- 상태: 진행, 일시정지
- 전이 규칙:
  - 진행 → 일시정지 (조건: 일시정지 버튼 / 앱 전환 / 브라우저가 보이지 않게 됨)
    - 함께 멈추는 것: 플레이어 차량, 컴퓨터 차량, 경기 시간. 교육용 마을의 등장 보행자·교통 신호도 함께 멈춤(해석: PRD "플레이"를 멈춘다는 뜻으로 확장)
    - 모든 운전 입력을 놓임으로 초기화
  - 일시정지 → 진행 (조건: 재개 동작만. 화면에 돌아온 것만으로는 재개하지 않음)
  - 일시정지 중에는 입력이 차량을 움직이지 않음
- 근거: 화면과 카메라 마지막 문단, 완성 기준(일시정지)

### ST-07 소리 활성화
- 상태: 비활성(시작 버튼 전), 활성, 소리 없음 진행(실패)
- 전이 규칙:
  - (접속) → 비활성 (소리 재생하지 않음)
  - 비활성 → 활성 (조건: 시작 버튼. 소리 설정에 따라 종류별로 재생)
  - 비활성/활성 → 소리 없음 진행 (조건: 활성화 실패 또는 음원 로딩·재생 실패. 화면 안내와 진행은 계속)
  - 활성 중 안내 음성 재생 → 배경음 낮춤 → 안내 끝나면 원래 크기
  - 종류별 켬 ⇄ 끔 (조건: 소리 설정 변경. 변경 시 저장 시도)
- 근거: 소리와 배경음악

### ST-08 교통 신호 (교육용 마을)
- 차량 신호: 초록 → 노랑 → 빨강 → 초록 (한국 기준. 회전 표시 등 구체 구성은 콘텐츠 설계)
- 보행자 신호: 빨강(멈춤) → 초록(건넘) → 초록 깜빡임 → 빨강
- 관계 규칙: 같은 횡단보도에서 보행자 초록과 그 횡단보도를 직진으로 지나는 차량의 진행 신호가 동시에 켜지지 않는다. 회전 차량은 보행자 초록 중에도 횡단보도를 지날 수 있다는 점이 "교차로의 회전 차량 주의하기"의 학습 대상이다(해석)
- 신호 전환 시점이 연습 진행(예: 정지 완료)에 맞춰 바뀔 수 있는지는 plan 결정
- 근거: 안전 연습과 교육 내용 표, 교육 표현 원칙

### ST-09 등장 보행자
- 상태: 보도 대기 → 횡단 중 → 건너기 완료
- 규칙: 보행자가 횡단 중인 경로로 플레이어 차량이 들어가면 잘못된 행동(→ ST-03 위험 직전 멈춤)
- 근거: 안전 연습과 교육 내용 표

### ST-10 참가 차량 주행 (레이싱)
- 상태: 정상 주행, 접촉 감속, 트랙 이탈, 복귀, 완주
- 전이 규칙:
  - 정상 주행 → 접촉 감속 → 정상 주행 (조건: 차량끼리 접촉. 파손·부상 표현 없음)
  - 정상 주행 → 트랙 이탈 → 정상 주행 (조건: 스스로 트랙에 돌아옴)
  - 트랙 이탈 → 복귀 → 정상 주행 (조건: 진행할 수 없음. 원래 진행 구간의 안전한 위치로. 진행도는 이탈 전 인정분을 넘지 않음)
  - 정상 주행 → 완주 (조건: 필요 바퀴 수를 정해진 순서와 방향으로 완료)
  - 후진·역주행 중에는 진행도가 늘지 않으며 결승선을 거꾸로 넘어도 바퀴로 세지 않음
- "진행할 수 없음"의 판정 기준(시간·위치)은 plan 결정
- 근거: 레이싱 규칙

### ST-11 브라우저 저장 기록
- 상태: 확인 전, 읽음(기록 있음), 읽음(기록 없음), 읽기 실패, 저장 기능 없음
- 전이 규칙:
  - 확인 전 → 각 상태 (실행 시작 시 1회)
  - 읽기 실패 / 저장 기능 없음 → 기록이 남지 않는다는 짧은 안내 + 현재 실행 상태로만 진행
  - 저장 시점: 세 상황 모두 완료 / 최고 기록 갱신 / 소리 설정 변경
  - 저장 시도 실패 → 현재 실행 값 유지 + 기록이 남지 않는다는 안내
- 근거: 브라우저에 남기는 기록

## Business Rules

### 차량과 운전
- **BR-001**: 차량 5종은 처음부터 모두 고를 수 있다. 잠금·해금·업그레이드가 없다. — 근거: 플레이 흐름 2, 첫 버전의 범위(차량 선택, 업그레이드 제외)
- **BR-002**: 차량 종류는 외형만 다르다. 최고속도·가속·제동·조향·후진 성능이 같고, 외형 차이로 충돌 판정이나 카메라 시야에서 유불리가 생기지 않는다. 같은 입력과 조건이면 운전 결과가 같다. — 근거: 첫 버전의 범위(차량 성능), 제공된 차량 모델 > 개발 시 확인할 사항, 완성 기준(차량 선택)
- **BR-003**: 컴퓨터 차량도 같은 공통 주행 규칙을 따른다. 난이도는 주행 경로와 반응으로만 조절하며 성능 값을 올려 조절하지 않는다(해석). — 근거: 레이싱 규칙
- **BR-004**: 조향과 액셀(또는 브레이크)을 동시에 누르는 두 손 조작을 허용한다. — 근거: 터치 조작
- **BR-005**: 액셀과 브레이크가 동시에 눌리면 브레이크를 우선한다. — 근거: 터치 조작
- **BR-006**: 버튼을 놓거나 터치가 취소되면 해당 입력은 즉시 놓임 상태가 된다. 누른 상태가 남지 않는다. — 근거: 터치 조작, 완성 기준(조작)
- **BR-007**: 전진↔후진 전환은 차량이 멈춘 상태에서만 된다. 움직이는 중의 전환 요청은 주행 방향을 바꾸지 않는다. 현재 방향은 그림으로 구분해 보여 준다. — 근거: 터치 조작
- **BR-008**: 일시정지나 화면 숨김이 일어나면 모든 입력을 해제하고, 재개 동작 전에는 어떤 입력도 차량을 움직이지 않는다. — 근거: 화면과 카메라(일시정지 문단), 완성 기준(일시정지)

### 안전 연습
- **BR-009**: 안전 상황은 안내된 정지·대기·출발 행동을 직접 수행하고 보행자 시점 안내를 경험해야 완료된다. 끝 지점 도착이나 시간 경과만으로는 완료되지 않는다. — 근거: 연습의 완료 기준
- **BR-010**: 잘못된 행동에는 사고·부상 장면이나 위협적인 소리 대신 짧은 설명과 해당 구간의 재시도를 준다. 교육용 마을에서 보도 진입·역방향 주행 같은 코스 이탈도 잘못된 행동으로 같은 방식을 적용한다(해석). — 근거: 교육 표현 원칙, 완성 기준(교육 진행)
- **BR-011**: 안전 연습에는 시간제한·목숨 수·실패 횟수 제한이 없다. — 근거: 플레이 흐름 4, 연습의 완료 기준
- **BR-012**: 위험 직전에 장면을 멈추는 연출은 학습 도움으로만 표현한다. 현실의 차량도 자동으로 멈춘다고 받아들일 안내를 쓰지 않는다. — 근거: 교육 표현 원칙
- **BR-013**: "깜빡이는 초록불에는 기다리기" 안내는 아직 횡단을 시작하지 않은 상황에만 쓴다. 이미 건너는 아이에게 도로 중간에서 멈추라고 안내하지 않는다. — 근거: 교육 표현 원칙, 안전 연습 표(신호 기다리기)
- **BR-014**: 차량 신호와 보행자 신호를 구분해 보여 주고 설명한다. 어떤 상태도 색만으로 설명하지 않고 그림·형태·짧은 음성을 함께 쓴다. — 근거: 교육 표현 원칙, 화면과 카메라
- **BR-015**: 세 안전 상황을 모두 완료하면 레이싱이 열린다. 완료 후 다시 연습하다 실패해도 완료와 레이싱 열림은 취소되지 않는다(해석: 완료는 "행동을 수행했다는 기록"). — 근거: 플레이 흐름 5, 연습의 완료 기준, 교육 표현 원칙 마지막 항목
- **BR-016**: 완료 전후 모두 원하는 안전 상황을 다시 연습할 수 있다. — 근거: 연습의 완료 기준
- **BR-017**: 운전 조작 성공이나 튜토리얼 완료를 보행 안전 이해의 증거로 평가하지 않는다. 따라서 "이해도 점수" 같은 평가 데이터를 두지 않는다. — 근거: 제품의 목적, 교육 표현 원칙
- **BR-018**: 등장 보행자는 교육용 마을에만 있고 전용 트랙에는 없다. — 근거: 레이싱 규칙, 용어집(교육용 마을·전용 트랙)
- **BR-019**: 보행자 시점 안내는 조작 없는 장면이다. 별도의 자유 보행 게임이나 보행자 조작 모드를 두지 않는다. — 근거: 안전 연습과 교육 내용 첫 문단, 용어집(보행자 시점 안내 Avoid)
- **BR-020**: 안전 연습에서 "빨리 통과하기"를 보상하지 않는다. 연습 완료 판정에 소요 시간이나 속도를 쓰지 않는다. — 근거: 교육 표현 원칙, 용어집(안전 행동)

### 레이싱
- **BR-021**: 레이싱 열림 조건은 (a) 저장된 튜토리얼 전체 완료 여부가 완료이거나 (b) 이번 실행에서 세 상황을 모두 완료한 경우다. 같은 실행 안에서 다시 잠기지 않는다. — 근거: 플레이 흐름, 브라우저에 남기는 기록, 완성 기준(레이싱 열기)
- **BR-022**: 참가 차량은 플레이어 1대와 컴퓨터 차량 3대다. 다른 사람이 참가하는 대전은 없다. — 근거: 레이싱 규칙, 첫 버전의 범위
- **BR-023**: 바퀴 수는 1 또는 2 중 하나로 고정하며 선택 화면이 없다. — 근거: 레이싱 규칙, 개발 중 결정할 항목
- **BR-024**: 약 5분은 예상 플레이 시간이다. 시간이 지났다는 이유로 경기를 강제로 끝내지 않는다. — 근거: 레이싱 규칙
- **BR-025**: 순위는 정상 진행 방향의 코스 진행도와 완주 순서로 정한다. 완주한 차량은 완주 순서대로, 완주하지 않은 차량은 진행도가 큰 순서로 앞선다. — 근거: 레이싱 규칙
- **BR-026**: 바퀴 완료는 정해진 순서의 구간을 정방향으로 모두 통과하고 결승선을 정방향으로 넘을 때만 인정한다. 후진으로 결승선을 반복해 넘거나 코스를 거꾸로 돌아도 추가 바퀴로 세지 않는다. — 근거: 레이싱 규칙, 완성 기준(접촉과 코스 이탈)
- **BR-027**: 차량끼리 접촉하면 파손·부상 표현 없이 감속한다. — 근거: 레이싱 규칙
- **BR-028**: 트랙 밖으로 나가 진행할 수 없으면 원래 진행 구간의 안전한 위치로 복귀한다. 경기 전체를 다시 시작하지 않으며, 복귀로 코스를 건너뛰거나 순위를 부당하게 올릴 수 없다. — 근거: 레이싱 규칙
- **BR-029**: 일시정지 동안 플레이어·컴퓨터 차량·경기 시간이 함께 멈추므로, 완주 시간에는 일시정지 시간이 들어가지 않는다. — 근거: 화면과 카메라(일시정지 문단), 완성 기준(일시정지)
- **BR-030**: 플레이어가 완주하면 결과 화면에 순위와 완주 시간을 보여 주고, 재도전 또는 시작 화면 복귀를 고를 수 있다. — 근거: 플레이 흐름 7, 레이싱 규칙
- **BR-031**: 최고 기록은 해당 트랙의 가장 짧은 정상 완주 시간이다. 새 완주 시간이 기존 기록보다 짧을 때만(또는 기록이 없을 때) 바꾼다. 순위와 차량 종류는 영향을 주지 않는다(해석). — 근거: 레이싱 규칙, 용어집(완주 기록)

### 저장·소리·출처
- **BR-032**: 저장하는 것은 튜토리얼 전체 완료 여부, 레이싱 최고 기록, 소리 설정 세 가지뿐이다. 이름·생년월일 등 개인정보를 받지 않고, 경기 중 위치나 미완료 연습을 재접속 후 이어 하지 않는다. — 근거: 첫 버전의 범위(저장), 브라우저에 남기는 기록
- **BR-033**: 저장 기능을 쓸 수 없거나 기록을 읽지 못해도 게임은 실행된다. 기록이 남지 않는다는 짧은 안내를 주고, 이번 실행에서 완료한 튜토리얼로 레이싱을 이용할 수 있게 한다. — 근거: 브라우저에 남기는 기록
- **BR-034**: 읽은 기록 값이 올바르지 않으면(예: 0 이하의 완주 시간, 알 수 없는 값) 그 항목을 "읽지 못한 기록"과 같이 취급한다(해석 — PRD 직접 근거 없음, BR-033의 확장). — 근거: 브라우저에 남기는 기록, `00_context.md`(저장 데이터 변조 시 동작)
- **BR-035**: 기록은 해당 브라우저에만 남는다. 로그인·기기 간 공유가 없으며, 브라우저 데이터를 지우거나 다른 기기를 쓰면 처음 상태로 시작한다. — 근거: 플레이 흐름 마지막 문단, 첫 버전의 범위
- **BR-036**: 소리는 어린이 플레이어가 시작 버튼을 누른 뒤에 활성화한다. — 근거: 소리와 배경음악
- **BR-037**: 한국어 안전 안내 음성이 나오는 동안 배경음 크기를 낮춘다. — 근거: 소리와 배경음악, 완성 기준(소리)
- **BR-038**: 배경음과 안내·효과음을 끌 수 있고 설정은 브라우저에 저장한다. 소리를 꺼도 핵심 안내는 그림과 시범으로 확인할 수 있다. — 근거: 소리와 배경음악
- **BR-039**: 음원 로딩이나 재생에 실패해도 화면 안내와 게임 진행은 계속된다. — 근거: 소리와 배경음악
- **BR-040**: 효과음은 위협적이지 않아야 한다. — 근거: 첫 버전의 범위(소리), 교육 표현 원칙
- **BR-041**: 차량 모델 크레딧에는 작품명·제작자·출처·라이선스 링크를 표시하고, 모델을 바꿨다면 바꾼 사실도 표시한다. — 근거: 제공된 차량 모델
- **BR-042**: 음원은 곡과 녹음 음원의 사용조건을 각각 확인하고 필요한 제작자·출처·라이선스를 표시한다. 비상업용이라는 이유만으로 사용 가능하다고 판단하지 않으며, 확인되지 않은 음원은 채택하지 않는다(해석). — 근거: 소리와 배경음악, 완성 기준(자료 사용)

### 접속·화면
- **BR-043**: 필수 파일의 로딩 상태를 보여 주고, 실패하면 다시 시도할 수 있게 한다. 차량 모델 5종은 모두 필수로 본다(해석: 완성 기준 "5종을 모두 선택하여 사용"). — 근거: GitHub Pages, 완성 기준(차량 선택)
- **BR-044**: 3D 표시 기능을 쓸 수 없는 환경에서는 빈 화면 대신 이해하기 쉬운 안내를 보여 준다. — 근거: GitHub Pages
- **BR-045**: 세로 화면에서는 가로로 돌리라는 안내를 보여 준다. 브라우저가 화면 방향을 강제로 고정할 수 있다고 전제하지 않는다. — 근거: 화면과 카메라

## Integration Points

- **정적 파일 호스팅(GitHub Pages, 저장소 하위 경로)**: 게임 → 호스팅 방향 읽기 전용. 화면 파일·차량 모델 5종·교육용 마을·전용 트랙·음원을 저장소 하위 경로에서도 올바르게 불러와야 한다. 필수 자료(화면·공간·차량 모델) 실패 시 재시도, 선택 자료(음원) 실패 시 소리 없이 진행. 서버 측 처리·로그인·데이터 전송 없음
- **브라우저 저장소**: 게임 ↔ 브라우저 양방향. 실행 시작 시 3개 항목을 읽고, 세 상황 완료·최고 기록 갱신·소리 설정 변경 때 쓴다. 쓸 수 없거나 읽을 수 없을 수 있음(BR-033). 사용자가 지우거나 바꿀 수 있으므로 읽은 값을 검사(BR-034)
- **브라우저 오디오 재생 제한**: 사용자 동작(시작 버튼) 이후에만 소리를 낼 수 있다는 모바일 브라우저 제약. 활성화 실패 시 소리 없이 진행
- **화면 표시 상태 변화(앱 전환·브라우저 숨김)**: 브라우저가 알려 주는 "보이지 않게 됨"을 받아 자동 일시정지와 입력 해제(ST-06)
- **화면 방향**: 가로/세로 상태를 받아 가로 화면 안내를 띄움. 방향 고정 요청은 전제하지 않음
- **터치 입력과 브라우저 기본 동작**: 게임 조작 중 스크롤·확대가 일어나지 않게 막는다. 터치 취소 신호를 입력 해제로 처리(BR-006)
- **3D 표시 기능 지원 여부**: 접속 시 확인해 미지원이면 안내 화면(BR-044)
- **외부 링크(원출처·라이선스 페이지)**: 크레딧에서 게임 밖 페이지로 나가는 단방향 링크. 개인정보를 보내지 않음
- **교육 내용 기준 출처(실행 중 연결 아님)**: 행정안전부 어린이 등하굣길·영유아 길 건너기 안내, 도로교통공단 교차로 보행자 안전 안내. 안전 상황의 행동과 문구를 구체화할 때 기준으로 삼는 콘텐츠 출처

## Assumptions / PRD 미정 항목 의존성

PRD "개발 중 결정할 항목"은 사용자 확인을 거친 미정 항목이라 질문하지 않고 의존성으로만 적는다.

- 바퀴 수(1 또는 2)와 경기 시간: 트랙 플레이 점검에서 고정 → 전용 트랙·레이싱 경기 속성 값
- 배경음악 곡·음원: 미선정 → 자료 출처의 음원 항목은 비어 있음, 채택 전 사용조건 확인 필요
- 모바일 성능 목표·최소 지원 환경: 초기 기기 점검에서 결정
- 3D 기술과 모델 변환: 기술 설계에서 결정
- 차량 바퀴 회전 표현: 모델 렌더링 점검에서 결정 → 차량 종류의 외형 표현에만 영향, 성능 규칙과 무관

분석 중 둔 가정(spec의 Assumptions 후보):
- 재도전은 같은 차량·같은 트랙의 새 경기다
- 연습 구간 시작과 경기 시작 때 차량은 전진·정지 상태다
- 경기 시간은 출발 신호부터 플레이어가 결승선을 넘는 순간까지이며 일시정지 시간은 빠진다
- 플레이어 순위는 플레이어가 완주하는 순간 확정된다
- 같은 실행 안에서는 직전에 고른 차량이 기본 선택이며, 재접속 시에는 기억하지 않는다
- 저장이 안 될 때 최고 기록과 소리 설정도 이번 실행 동안만 유지된다
- 소리 설정 기본값은 모두 켬이다
- 크레딧은 시작 화면에서 들어간다
- 형식 변환·크기·방향 조정도 "모델 변경"으로 보아 변경 사실을 표시한다(보수적 해석)

## 다른 분석가에게 전달

**edge-analyst에게 — 상태가 겹치거나 경합하기 쉬운 곳**
- 입력 고착: 터치 취소·여러 손가락·화면 숨김 직전 입력(BR-006, BR-008)
- 정지 판정 경계: "완전히 멈춤"과 후진 전환 가능 시점, 저속 미끄러짐(ST-04)
- 일시정지 중 화면 방향이 세로로 바뀌거나, 세로 상태에서 앱 전환이 겹치는 경우(ST-01, ST-06)
- 결승선 근처에서 후진·전진 반복, 복귀 직후 결승선 통과, 출발 직후 첫 결승선 통과(BR-026, BR-028)
- 플레이어와 컴퓨터 차량이 거의 동시에 결승선을 넘을 때 순위(BR-025)
- 세 번째 상황 완료와 저장 실패가 동시에 일어날 때, 최고 기록 갱신 중 저장 실패(ST-02, ST-11)
- 저장 기록 값이 바뀌었거나 일부만 남은 경우(BR-034)
- 보행자 시점 안내 도중 일시정지·소리 실패(ST-03, ST-07)
- 위험 직전 멈춤 연출과 사용자 일시정지가 겹칠 때(ST-03, ST-06)

**functional-analyst에게 — User Story에 영향을 주는 엔티티 제약**
- 레이싱 Story는 레이싱 열림에 의존한다. 독립 검증은 "저장된 전체 완료 기록이 있는 상태"를 시작 조건으로 두면 된다(BR-021)
- 안전 상황 3개는 각각 독립 검증이 가능하다(상황별 완료 판정이 따로 있음)
- 저장·소리·크레딧은 다른 Story 없이도 시작 화면에서 검증 가능한 단위다
- 완료 판정에 시간·도착을 쓰지 않으므로 수용 기준도 "행동 수행"으로 적어야 한다(BR-009, BR-020)
